## Socle commun et présence par environnement

- `DATABASE_URL` ou `POSTGRES_URL` ; `CLARA_CREDENTIALS_ENCRYPTION_KEY` pour les credentials et états OAuth ; `CLARA_WORKSPACE_ID` / `CLARA_MD_WORKSPACE_ID` ; `CLARA_AUTH_APP_ORIGIN`.
- Connexion **opérateur OS**, différente de la connexion fournisseur : `CLARA_AUTH_GOOGLE_REDIRECT_URI` avec les clés Google ci-dessus, ou `CLARA_AUTH_MICROSOFT_CLIENT_ID`, `CLARA_AUTH_MICROSOFT_CLIENT_SECRET`, `CLARA_AUTH_MICROSOFT_TENANT_ID`, `CLARA_AUTH_MICROSOFT_REDIRECT_URI` ; `CLARA_AUTH_BOOTSTRAP_EMAIL` est un contrôle bootstrap prévu par le code, pas une identité autorisée par simple email.
- Tokens/refresh tokens, URL webhook Make, clé Stripe et prix ne doivent pas être remplacés par des variables inventées : ils sont stockés dans les connexions/credentials existants. GitHub OAuth OS n’est pas dans le registre de providers actuel ; une identité serveur disponible ne prouve pas cette connexion.
- L’inventaire JSON contient tous les noms de variables lus par cette base applicative, avec fichiers source. `NODE_ENV`/`PATH` sont du runtime ; les limites des workers et flags optionnels ne sont pas des secrets à créer aveuglément.
